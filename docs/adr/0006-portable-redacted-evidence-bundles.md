# ADR 0006: Portable redacted JSON evidence bundles with canonical hashes

- Status: accepted
- Date: 2026-09-15

## Context

Evidence must move from a local session into code review or CI without a hosted service, raw workspace paths, or stored secrets. A bundle must remain inspectable with ordinary local tools, retain enough provenance for a reviewer to evaluate the claim, and identify accidental or untrusted modification after export.

Repository-controlled content, adapter output, and imported bundle files remain untrusted. The supervisor must construct the export from canonical retained evidence and must own verification semantics.

## Decision

Version 1 exports one human-readable JSON object generated by the authenticated local supervisor. It contains:

- retained session metadata and canonically sequence-ordered events;
- explicit projections for policy decisions and Git diff evidence;
- the deterministic, versioned cost report when provider/model pricing is known;
- supervisor and redaction-policy versions;
- export-time path and secret-redaction replacement counts; and
- a manifest containing SHA-256 hashes for every top-level evidence section and the complete content envelope.

Hash inputs use UTF-8 JSON with lexicographically sorted object keys. The `manifest` is excluded only from the content-envelope hash, preventing circularity. A verifier recomputes the content and section hashes and returns a versioned valid/invalid result. Event order is always by supervisor-assigned sequence before construction.

The supervisor applies the ordinary recursive secret redactor and an export-only absolute filesystem-path scrub before hashing. Relative repository paths, workspace labels, evidence grades, unknown reasons, and redaction placeholders remain available for review. Clients can save the already-redacted bundle but cannot request raw export.

## Consequences

- `agent-contract export <session-id> --output <file>` and the VS Code command create locally inspectable artifacts without a hosted dependency.
- `agent-contract verify <file>` delegates hash verification to the local supervisor and exits with the integrity error code for invalid bundles.
- Hash-only v1 detects changes when the manifest has not also been replaced. It does not prove who created a bundle and cannot resist an attacker who rewrites content and all hashes. Signed bundle provenance is a future versioned capability, not an implied v1 claim.
- Imported bundle input is not persisted by verification and is never used as authoritative evidence for policy enforcement.
- The size-limited local verification endpoint accepts up to 2 MiB of JSON; larger artifacts need a streamed artifact protocol before they can be verified through this API.
